# mission-control — Comprehensive Code Review (2026-05-30)

> Multi-agent static review of the full codebase on branch `feat/console-design` (= `main` + the Console design re-skin). Backend: 10 entities, audit/undo, semantic search, auth (78 tests). Frontend: CRUD for all entities + search + activity + the Console design (24 tests). Read-only review — no code was changed. This document is findings + a prioritized fix plan.

## Executive summary

The codebase is **healthy and well-architected**. The core invariant — domain services are the sole writers; every mutation records a reversible audit entry — holds across the entities, transaction discipline is correct (services flush, routers commit, session rolls back on error), there is no raw SQL/injection, auth is gated at the router level on every router, and the test suite uses a real Postgres with savepoint isolation (no mocks for the DB).

The findings are concentrated in **predictable places**: error-handling at the FK/unique-constraint boundary (unhandled `IntegrityError` → 500 instead of 4xx), a few **silent-success paths** in revert/indexing, **frontend edit-time FK clearing** and **light-theme Tailwind leftovers** on the CRUD pages under the new dark theme, missing **enum validation**, and **API breadth** the SPEC promises but isn't built yet (list filtering/pagination, audit filters). Two items rise to **CRITICAL** (insecure default session secret; embedding failure can roll back a user's write). Nothing is a data-corruption bug in the happy path.

**Top 7 to fix first:** C1 (session-secret fail-fast), C2 (decouple indexing from the write txn), I1 (global `IntegrityError`→409/422), I2 (revert-create silent no-op), I3 (revert doesn't re-index), I13 (session fixation), I4 (can't clear an FK on edit).

## Part B — Findings

Severity: **CRITICAL** (fix before any real use) · **IMPORTANT** (fix soon) · **MINOR** (cleanup/polish). Deduplicated across the 8 review passes.

### CRITICAL

**C1 — Insecure default `session_secret` ships in code and `.env.example`** · `app/config.py:10`, `.env.example`
Default `"dev-insecure-change-me"` signs session cookies. A self-hoster copying `.env.example` runs prod with a publicly-known signing key → anyone can forge a session and authenticate.
→ Fail-fast: raise on startup if `environment != "development"` and secret is still the default. Replace the `.env.example` value with a `# generate: python -c "import secrets; print(secrets.token_hex(32))"` placeholder.

**C2 — Embedding failure inside the write transaction rolls back the user's CRUD write** · `app/search/index.py:29`, `app/search/embedder.py:34`
`index_subject()` calls `embed_text()` with no try/except, inside the same session as the entity write (before `commit`). With `EMBEDDINGS_PROVIDER=openai`, any API error/timeout/rate-limit propagates → 500 → the user's create/update is **rolled back and lost**. (With the `fake` default it can't fail, but the openai path is one config flag away.)
→ Decouple indexing from the write's success: wrap the embed/index in try/except (log + skip the chunk), or move indexing to a background task/outbox (the P3-planned worker). The CRUD write must commit independently of indexing.

### IMPORTANT

**I1 — Unhandled `IntegrityError` → 500 across all create/delete paths** · all `app/services/*.py`, `app/api/*.py`
No layer catches `IntegrityError`. Concrete 500s a normal user hits: invalid FK on `POST /projects|tasks|people|entity-tags|relationships` (bad `context_id`/`company_id`/`project_id`/`tag_id`/person ids → Postgres `23503`); duplicate unique on `POST` of an existing `slug`/`name`, a duplicate relationship edge (`uq_relationship_edge`), a duplicate entity-tag (`uq_entity_tag`); deleting a parent that still has FK children (no `ondelete` → `RESTRICT` → 500); and **revert-of-delete** re-inserting a row whose slug now collides.
→ Add a single global FastAPI exception handler mapping `IntegrityError` → **409** (unique/FK-restrict) / **422** (FK-not-found, PG `23503`) with a readable detail. Optionally add `ondelete` policies where cascade/set-null is desired.

**I2 — Revert of a "create" silently 200-no-ops when the entity is already gone** · `app/audit/revert.py:25-32, 51`
The create-branch only deletes `if obj is not None`, but `audit.reverted=True` is set unconditionally and 200 returned — no compensating audit row, nothing undone. Misleading undo UX; breaks the "every revert writes a compensating row" invariant (SPEC §9).
→ Raise `409`/`404` when `obj is None` in the create-revert branch (mirror the update branch).

**I3 — `revert_audit` does not re-index → search index drifts on every undo** · `app/audit/revert.py`
Revert writes the compensating audit row but never calls `index_subject`/`deindex_subject`. A reverted delete recreates the row but leaves no chunk; a reverted create leaves a stale chunk; a reverted update leaves pre-revert text in the index.
→ After each branch, call the matching `index_subject`/`deindex_subject`, exactly as the services do.

**I4 — You can't clear an FK on edit (silent stickiness)** · `people.tsx:37`, `tasks.tsx`, `relationships.tsx`
`buildPayload` *omits* empty optional FK fields. Correct for create, **wrong for PATCH**: clearing the Company/Context/Project select sends no key, so the backend leaves the old value. Once set, an FK can never be unset from the UI.
→ On update, send `field: null` (not omit) when the select is cleared. Differentiate create vs update in `buildPayload`.

**I5 — `projects.tsx` submits empty `context_id` + no required guard** · `src/routes/projects.tsx:75-84, 141`
Unlike the other pages it always sends `context_id: form.context_id` (required FK). Submitting with no context selected sends `""` → 500, with no UI feedback.
→ `disabled={!form.context_id}` on submit (or `required` on the select) and omit/validate before send.

**I6 — ⌘K command palette loses the typed query** · `AppShell.tsx` (CommandPalette) → `navigate({ to: "/search" })`
Pressing Enter routes to `/search` but drops the query (the palette's local state isn't threaded; `SearchPage` keeps its own state). You always land on an empty search.
→ `navigate({ to: "/search", search: { q } })` + a typed search-param schema on the route read via `Route.useSearch()`. (This also fixes the known no-q deviation.)

**I7 — CRUD pages use light-theme Tailwind classes — low-contrast under the dark Console theme** · every `src/routes/*.tsx` (e.g. `text-gray-500`, `bg-gray-400`, `text-gray-900`, `p-6 space-y-6`), `RequireAuth.tsx`, `placeholder.tsx`
Page headings, Edit/Cancel buttons, and help text use Tailwind gray scales that read as light-mode colors → muddy/near-invisible on the dark surfaces. The shell, login, dashboard, and the *primitives* are fully Console; the page *chrome* is not.
→ Replace page-level Tailwind utilities with Console primitives/tokens: wrapper `style={{ padding: "24px 32px", display:"flex", flexDirection:"column", gap:24 }}`, headings `className="title"`, Edit as `btn ghost sm`, Cancel as `Button className="ghost"`, help text `className="meta"`. Restyle `placeholder.tsx` to the design's `well ticks` pattern.

**I8 — `useRevert` invalidates the entire query cache** · `src/features/audit/api.ts:15`
`qc.invalidateQueries()` (no key) refetches every list **plus `["me"]`** on each undo → request storm and bypasses `me`'s staleTime.
→ Scope to the reverted entity: `qc.invalidateQueries({ queryKey: [result.entity_type] })` (+ `["audit"]`).

**I9 — Enum fields accept any string (no validation)** · all `app/schemas/*.py`, all models
`status`/`priority`/`kind`/`category`/`type`/`actor`/`action`/`surface` are bare `str` with no Pydantic `Literal` and no DB `CHECK` (SPEC §6 explicitly asked for CHECK). The API (and the future AI agent) can persist `status="potato"`; revert re-inserts bad values unchecked.
→ Add `Literal[...]` to the schemas for every Appendix-A enum (boundary validation). Optionally add `CHECK` constraints for the highest-risk columns in a new migration.

**I10 — `AuditOut` omits `agent_run_id`** · `app/schemas/audit.py`
The model has it; the response schema drops it. Needed for the Activity view's "group by run / undo whole run" (SPEC §9/§12).
→ Add `agent_run_id: uuid.UUID | None`.

**I11 — `GET /audit` lacks `entity_type`/`surface` filters and bounds** · `app/api/audit.py:17`
SPEC §11/§12 want filtering by entity and surface (the Activity view defaults to `surface != ui`). Also `limit` is unbounded (`limit=10000000` allowed), unlike `/search` which uses `Query(ge=1, le=100)`.
→ Add `entity_type`/`surface` query params + `limit: int = Query(default=100, ge=1, le=1000)`.

**I12 — List endpoints have no filtering or pagination** · all `list_*` services
SPEC §11 specifies filtering (context/project/tag/status/date) + pagination. Every list returns all rows. At volume the Tasks/People lists return everything.
→ Add filter params + `LIMIT/OFFSET` (or cursor). Highest priority for tasks/people/observations.

**I13 — Session fixation: login doesn't clear the prior session** · `app/api/auth.py:18`
`request.session["user_id"] = ...` without `request.session.clear()` first.
→ `request.session.clear()` before setting `user_id`. One line.

**I14 — Command palette has no focus trap / dialog semantics / arrow-nav** · `AppShell.tsx` (CommandPalette)
Focuses input + Escape-to-close (good), but Tab escapes the modal, no `role="dialog" aria-modal`, no ↑/↓ between results.
→ Add `role="dialog" aria-modal="true" aria-label`, trap Tab, add ArrowUp/Down result navigation.

**I15 — `.iconbtn` has no `:focus-visible` ring** · `src/styles/console.css` (after l.267)
`.btn` has the ring; icon-only buttons (voice, settings, nav collapse, Aya close, hamburger) show no keyboard focus indicator (WCAG 2.4.7).
→ `.iconbtn:focus-visible { outline: 2px solid var(--signal); outline-offset: 2px; }`.

**I16 — `color-scheme` conflict** · `src/index.css:4` (`:root { color-scheme: light dark }`) vs `console.css:121` (`html { color-scheme: dark }`)
Native controls (date pickers, selects) may render in the OS scheme rather than the app theme.
→ Remove `color-scheme: light dark` from `index.css`; rely on console.css's `html` / `html[data-theme="light"]` rules.

**I17 — `chunk` migration hardcodes `Vector(1536)` while the model uses `settings.embeddings_dim`** · `alembic/versions/0014_chunk.py:21` vs `app/models/chunk.py:21`
Changing `embeddings_dim` silently desyncs model and DB.
→ Drive the migration dim from the same setting/constant, or add a prominent comment that changing the dim requires a new migration.

**I18 — High-value test gaps** · `backend/tests/`
(a) **No test asserts auto-index-on-write** — CRUD goes through `index_subject`, but no test inspects `Chunk` after a `POST/PATCH/DELETE`; dropping an `index_subject` call would be invisible. `test_search_api.py` even calls `/admin/reindex` first, masking it.
(b) **Revert update/delete untested for FK & polymorphic entities** — only Context (all 3) + Project (create only). No `revert_update`/`revert_delete` for Project/Person/Task/Relationship/Observation/Tag.
(c) **Compensating-audit row not asserted** on update/delete revert (only create-revert checks it).
(d) **Unique/FK error-path status codes untested** (ties to I1) — would have surfaced the 500s.
→ Add: one parametrized chunk-after-write test across the 6 indexable services; full create/update/delete revert for one FK + one polymorphic entity (asserting the compensating row); a duplicate-slug + bad-FK test per relevant entity asserting the chosen 4xx.

**I19 — Dashboard `toggleTask` has no error handling** · `src/routes/index.tsx:255`
On mutation failure the row stays visually checked while the server task is still open; un-checking only updates local UI (sends nothing).
→ Add `onError` to revert local state; consider TanStack optimistic-update.

**I20 — Relationship & Tag services skip indexing; `_INDEXABLE` omits them** · `app/services/relationship.py`, `tag.py`, `app/api/admin.py:17`
Inconsistent with the "every mutation → audit + index" invariant. Defensible (relationship/tag aren't in SPEC §8's indexable list) but undocumented and means their `notes`/`name` aren't searchable.
→ Decide intent and document it. If they should be searchable, add the index calls + extend `_INDEXABLE` (and ideally derive `_INDEXABLE` from a single registry like `ENTITY_MODELS`).

## Part C — Architecture & duplication (recommendations, not bugs)

- **Abstract the backend services** (the strongest DRY win): the 10 services are structurally identical (~350 lines of copy-paste). A `make_crud_service(entity, Model, Create, Update)` factory with an optional `list_stmt_fn` escape hatch (for observation/entity_tag/entity_link filters) cuts this to ~40 shared lines + per-entity config, mypy-clean, low-risk (behavior is already test-covered per entity). **Leave the FastAPI routers and the frontend pages as-is** — router abstraction hurts OpenAPI readability, and pages will diverge (detail panes, bulk actions). For the pages, extract a `useCrudForm` hook (the repeated `form/editingId/handleChange/handleSubmit/handleCancel` wiring) without a full page factory.
- **Single source of truth for indexable entities**: derive `admin.py:_INDEXABLE` from a registry (mirror `audit/registry.ENTITY_MODELS`) so new entities can't be forgotten.
- **`surface` is hardcoded `"ui"`** in routers — correct for the human path; document that the future AI agent calls services directly with its own surface (it must, since `surface` is set at the call site, not derived from the request).
- **Split `AppShell.tsx` (1134 lines)** into `shell/` subcomponents (TopBar, LeftNav, AyaDock, CommandPalette, SettingsPopover, Toasts) for readability.
